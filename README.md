# 好好生活 · 人生指南行动追踪

把 [《高性价比人生指南》](https://github.com/eternity4719/HowToLiveBetter) 的 34 章、765 条建议变成可安排、可打卡、可回顾的个人行动计划。

**在线使用：[打开好好生活](https://zj05409.github.io/life-action-tracker/)**

## 开始使用

1. 打开“完整指南”，搜索关键词或按章节、证据、花钱、用时、状态筛选。
2. 选择一两条适合自己的建议，点击“加入计划”。
3. 在详情里写笔记、拆步骤、设置日期。点击“今天做”后，事项会出现在“今日行动”。
4. 一次性行动完成后勾选；持续行动设置为每日／每周／每月，按周期打卡。
5. 在“进度回顾”查看行动足迹与各章进度。暂不适用的事项可单独标记，从完成率分母中排除。

### 在手机上逐条发现

手机打开首页会进入单条行动信息流，下方可直接切换“发现、今天、计划、足迹、设置”。

- **左滑 / 稍后看**：只跳过本轮，不会更改事项的适用性或已有进度。看完这一轮后可以重新查看稍后事项。
- **右滑 / 今天做**：加入计划并安排到今天，接着显示下一条。
- **撤销**：逐步返回并恢复滑动前的完整状态，最多保留最近 30 步。同一标签页刷新后仍可撤销；关闭该标签页后浏览会话结束。若事项后来有了新的笔记、打卡或导入修改，会保留较新的进度。
- 卡片内容可上下滚动阅读，短拖、纵滑和取消手势不会执行选择；所有滑动都有对应按钮，也支持卡片上的左右方向键。
- “逐条发现 / 完整列表”可随时切换，搜索和章节筛选继续可用。发现只展示尚未加入计划的待行动建议，完整列表仍包含全部 765 条。

桌面默认保留完整列表，也可以切换到逐条发现。

指南是备选单。不同人生阶段、地区和身体情况适用的建议不同，完整原文和备注均可在条目内展开，不需要强行做完不适用的事项。

## 数据与隐私

- 无需登录，无后端，无分析统计或第三方脚本。
- 计划、笔记、步骤和打卡只保存在当前浏览器：行动进度使用 localStorage，滑动撤销快照使用当前标签页的 sessionStorage，**不会提交到仓库或上传到网络**。清空进度也会清除撤销快照。
- 同一网站地址、同一浏览器中刷新与重新打开会保留进度；不同浏览器、地址、设备不会自动同步。
- 定期点击“备份数据”导出 JSON。换浏览器或清除网站数据前务必备份。
- 导入会合并数据：同条目保留更新时间较新的记录，打卡日期取并集；当前周目标不变。恢复损坏存储另有明确的恢复入口。
- 首次联网打开并完成缓存后可离线使用。网站更新保留个人进度。
- 日期只在工具内安排，不会在页面关闭后发送通知。

在 Mac Safari 中可通过“文件 → 添加到程序坞”作为独立窗口打开，也可直接收藏网址。

## 本地运行

网页为零运行时依赖的静态文件，可直接双击 `index.html`；推荐使用稳定的 HTTP 地址，确保浏览器存储和离线缓存行为一致：

```sh
python3 -m http.server 4173
```

在浏览器打开 `http://localhost:4173`。本地与 GitHub Pages 的进度各自保存，可通过 JSON 备份迁移。

## 验证与构建

需要 Node.js 20+，无依赖安装步骤：

```sh
npm run check
npm run build
```

`dist/` 只包含公开应用资源，不会复制备份、日志、测试产物、Git 数据。构建为缓存生成内容指纹。

`tests/mobile-feed.cjs` 为可选的 WebKit 浏览器回归检查，需要外部 Playwright 与 WebKit 运行环境。启动本地预览后运行该脚本，`QA_URL` 可指定其他测试地址；全部测试使用独立临时浏览器，不操作个人浏览器档案。

## GitHub Pages 部署

当前交付分支为 `feat/life-action-tracker`。仓库的 **Settings → Pages → Source** 使用 **GitHub Actions**。此分支 push 后，`.github/workflows/pages.yml` 自动验证、构建并部署 `dist/`。也可在 Actions 手动运行。

迁移仓库时，修改工作流的分支触发条件即可；所有资源均使用相对路径，兼容 GitHub Pages 项目子目录。若网站网址改变，用备份迁移个人进度。

更新内容需要先克隆上游，再运行：

```sh
node scripts/import-guide.mjs /path/to/HowToLiveBetter
node scripts/import-guide.mjs /path/to/HowToLiveBetter --check
npm run check
npm run build
```

条目 ID 使用章节号和规范化标题的哈希，避免上游插入新条目导致个人进度错位。上游重命名标题或移动章节时视为新条目；旧进度仍保留于导出备份，不会错误套用到另一项。导入旧快照备份时，不属于当前内容的条目会明确显示跳过数量。内容更新需人工审查后提交，不会后台自动改变建议。

正文保留原始六个字段及适用说明，转换为行动卡片；本工具独立开发，非原作者官方产品。指南中的法律、医保与社保按中国大陆制度编写，实际办理以当地现行规定为准。
